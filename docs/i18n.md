# Localization & Message Formatting (i18n)

ClickPortals formats all player-facing text using [Adventure MiniMessage](https://docs.advntr.dev/minimessage/format.html) and supports per-player localization based on each player's Minecraft client language setting.

## Bundled Languages

On first startup (and on `/cp reload`), ClickPortals extracts the built-in translation files into `plugins/ClickPortals/lang/`:

- `en_US.yml` — English (United States)
- `ja_JP.yml` — Japanese (Japan)

## Configuration (`config.yml`)

```yaml
language:
  # Fallback locale used for console messages, item names, and unsupported client locales (e.g. en_US, ja_JP)
  default-locale: en_US
  # Whether to automatically switch player-facing messages and holograms to match the player's client language
  use-client-locale: true
```

### Fallback Order

When rendering a message for a player:

1. If `use-client-locale` is `true`, ClickPortals looks up an exact locale match (e.g. `ja_JP`), then a language-only match (e.g. `ja_*`).
2. If no bundle matches the client locale (or `use-client-locale` is `false`), ClickPortals falls back to `language.default-locale`.
3. Any key omitted from a customized file is automatically filled from the bundled `en_US.yml` defaults.

> [!NOTE]
> Crafted Aetheryte items use `language.default-locale` for their item name and lore because item stacks are shared across inventories and recipes. Holograms (`TEXT_DISPLAY`), Dialog UIs, and chat messages dynamically adapt to each viewer's client language.

## Customizing & Adding Translations

1. Edit `plugins/ClickPortals/lang/en_US.yml` or `plugins/ClickPortals/lang/ja_JP.yml` using standard MiniMessage tags (such as `<aqua>`, `<bold>`, `<gradient>`).
2. To add a new language, create `plugins/ClickPortals/lang/<locale>.yml` (for example `de_DE.yml` or `zh_CN.yml`). You only need to include the keys you wish to translate; any missing keys fall back to `en_US.yml`.
3. Run `/cp reload` to apply changes immediately without restarting the server.

## Placeholders Reference

All user-supplied values (such as Aetheryte names and player names) are injected as unparsed literals so players cannot inject MiniMessage formatting tags.

| Key | Placeholders |
|---|---|
| `hologram.title` | `<name>` |
| `dialog.create.description` | `<world>`, `<x>`, `<y>`, `<z>` |
| `dialog.create.variation` | `<variation>` |
| `dialog.create.default-name` | `<player>` |
| `dialog.warp.title`, `dialog.warp.body-empty`, `dialog.warp.body-select` | `<name>` |
| `dialog.warp.destination-available`, `dialog.warp.destination-unavailable` | `<name>`, `<cost>` |
| `dialog.warp.distance-blocks` | `<blocks>` |
| `dialog.warp.tooltip-allowed` | `<world>`, `<x>`, `<y>`, `<z>`, `<distance>`, `<cost>` |
| `dialog.warp.tooltip-denied` | `<world>`, `<x>`, `<y>`, `<z>`, `<distance>`, `<cost>`, `<reason>` |
| `dialog.remove.title`, `dialog.remove.body` | `<name>` |
| `aetheryte.created`, `aetheryte.removed`, `warp.success` | `<prefix>`, `<name>` |
| `error.clearance-insufficient` | `<prefix>`, `<width>`, `<height>` |
| `error.limit-reached-global` | `<prefix>`, `<max>` |
| `error.limit-reached-variation` | `<prefix>`, `<variation>`, `<max>` |
| `error.*` | `<prefix>`, `<reason>` (for `error.warp-denied`) |
| `command.given-item` | `<prefix>`, `<player>`, `<amount>` |
| `command.unknown-variation` | `<prefix>`, `<variation>` |
| `command.console-specify-player`, `command.reloaded` | `<prefix>` |
